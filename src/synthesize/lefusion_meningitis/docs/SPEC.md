# Agent 操作规范（SPEC）


## 1. 文档目的

定义 Agent 的权限边界、工作区范围、执行流程、沟通方式和交付要求，确保每次操作可追踪、可复核、可回退。

## 2. 工作区

- 项目根目录：`lefusion_meningitis/`
- 文档目录：`lefusion_meningitis/docs/`
- 默认允许修改：项目源代码、测试、配置和本目录中的文档。
- 数据、模型权重、密钥和其他敏感文件：未经明确授权不得读取、上传或提交。
- 所有路径均以项目根目录为基准记录，避免使用机器相关的绝对路径。

## 3. 权限边界

### 允许

- 阅读项目文件并分析现有实现。
- 创建或修改实现任务所需的源代码、测试和文档。
- 执行非破坏性的格式检查和构建验证。
- 在执行前记录计划，关键决策记录到 `decisions/`。

### 需要确认

- 删除或覆盖重要文件、批量重命名、修改数据集或模型权重。
- 修改实验协议、评估指标或其他会影响研究结论的设定。
- 实现计划之外的功能或优化。

### 禁止

- 泄露凭据、个人信息、医疗隐私或未脱敏数据。
- 通过不可追溯的方式绕过测试、审查或权限控制。
- 在没有备份或明确授权的情况下执行不可恢复的破坏性操作。

## 4. 行为规范

1. 开始任务前先阅读相关代码、测试和本规范。
2. 优先采用最小、可验证的实现；不顺手重构无关代码。
3. 复杂任务先在 `plans/` 建立计划，并随着进展更新状态。
4. 发现影响范围较大的取舍时，在 `decisions/` 新建决策记录。
5. 完成后运行适用的测试或检查，并在回复中说明结果和未解决风险。
6. 不确定时保留现状并提出问题，绝对不擅自扩大任务范围。

## 5. 交付格式

每次任务完成时，应说明：变更摘要、涉及文件、验证命令及结果、遗留事项（如有）.
